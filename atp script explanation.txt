The new MATLAB script replaces the first version's single-limit check with a fourteen-stage pipeline that no longer asks "does each unit pass with margin to spare" one test at a time, but instead lays every test out as a column in a report-by-test grid so it can judge redundancy from how the tests behave together across the whole production history. It first cleans the two CSV exports (with a fallback that remaps the legacy CITED/METABASE column names), builds the mean, standard deviation, limits, and Cpk for every test, then separates normal units from "dead" ones (reports where an abnormally high fraction of tests failed) so that a single broken module can't make an otherwise-healthy test look indispensable, while still counting those failures toward coverage. For each test it estimates the probability of a future unit slipping past the limit three different ways (from the normal curve, from the raw rate of past exceedances, and from a model fitted to just the worst-case tail) and keeps the most pessimistic of the three, so nothing is called redundant on optimistic math. It also flags any test whose readings are slowly drifting toward a limit even if none has failed yet.

The heart of it is deciding which tests are genuinely saying the same thing. It groups tests with similar names using Jaccard distance (the share of name-tokens two tests have in common), then within each group asks, via an R2, how much of one test's pass/fail margin can be predicted from the others in the group. A high R2 means that test is redundant because its result is already implied by its neighbors. The script also pools each cluster with an empirical-Bayes model that shrinks a single test's failure-rate estimate toward its family and discounts the effective sample size by how correlated the tests are, so a group of tests that always move together isn't mistaken for many independent confirmations. A single test is only marked removable if it has zero real failures, a comfortable margin, enough history to be trusted, and a low statistical upper bound on its true failure rate; a whole group is removed only when the group collectively clears those same bars.

Before finalizing, it mines sets of tests that historically fail together and forces at least two survivors from each such set to stay, so no failure signature loses all its detectors. It also labels each redundant cluster with the parameter ranges (frequency bands and the like) over which it has always passed, and separately calls out the "key" tests that are irreplaceable because they are the only thing catching certain failures. The output is not a single list but roughly a dozen CSVs plus a printed report: a full per-test table, the individually redundant tests, the redundant clusters, the co-failure modes and their members, the key tests, fully-redundant and never-failed digit groups, and a concrete "keep vs. cut" split that reports the minutes saved per module alongside a worst-case estimate of how many real failures the cuts would have let escape.
